# Contributing — Your Energy

Team workflow for the GoIT "Your Energy" project. Read this before opening your first PR.

## Branch model

```
main      ← protected, always deployable; only updated via PR from dev
 └─ dev   ← integration branch; all feature branches start here and merge back here
     ├─ feat/12-exercise-filters
     ├─ feat/13-categories-list
     └─ ...
gh-pages  ← generated by the deploy workflow; never edit by hand
```

- **`main`** — production. No direct pushes. Updated only by merging `dev` via PR.
- **`dev`** — integration. Branch from it, merge back into it.
- **`gh-pages`** — created/updated automatically by the deploy workflow.

## Branch naming

```
<type>/<ticket-id>-<short-slug>
```

- Lowercase English, words separated by hyphens (kebab-case). No uppercase, no spaces.
- `ticket-id` comes from the tracker; `short-slug` is 2–4 words describing the ticket.

| type | when | example |
|------|------|---------|
| `feat` | new feature / component | `feat/12-exercise-filters` |
| `fix` | bug fix | `fix/27-email-validation` |
| `chore` | tooling, deps, config | `chore/5-eslint-setup` |
| `docs` | documentation | `docs/9-contributing` |
| `ci` | deploy / pipelines | `ci/10-gh-pages-deploy` |
| `refactor` | refactor without behavior change | `refactor/14-api-service` |

One ticket = one branch = that ticket's partial, CSS file, and JS file.

## Commit convention

Conventional Commits, with the ticket id in the footer:

```
<type>: <short description> (#<id>)
```

Example: `feat: add exercise filters (#12)`

## Pull request rules

- Target branch: **`dev`** (never `main` directly).
- PR title: `[#<id>] Short description` — e.g. `[#12] Exercise filters`.
- Keep a PR to a single ticket: its partial, its CSS file, its JS file, and the lines that connect them.
- At least **1 approving review** before merge.
- **Do not edit** lead-owned shared files in a feature PR: `src/main.js`, `src/favorites.js`,
  `src/js/api/energyApi.js`, `src/js/constants/`, `src/css/common/`.
  In `src/index.html` / `src/favorites.html` add only your own `<load>` line.
  In `src/css/main.css` add only your own `@import` line.
  Create your markup file in `src/partials/`.

### PR checklist

- [ ] `npm run lint` passes with no errors
- [ ] `npm run build` succeeds
- [ ] Browser console has no errors and no `console.log`
- [ ] Works at all three breakpoints (mobile / tablet / desktop)
- [ ] Only my partial, my CSS, my JS, and the lines that connect them changed

## Local development

```bash
npm install
npm run dev      # start dev server
npm run build    # production build
npm run preview  # preview the production build
npm run lint     # lint
```

## Branch cleanup

After a ticket is merged, delete its feature branch. At project end only **`main`** and
**`gh-pages`** should remain.
